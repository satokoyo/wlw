# Wonder Deck 1.0.3 検証結果

実施日：2026年9月22日。Wonder.NETにログイン済みのPC版Chromeと、Node.js標準テストを使用しました。

## 実サイトでの確認

cast=2（ピーター・ザ・キッド）の検証開始時のデッキ全体を記録し、変更後に復元しました。cast=36（マリク）は取得・切り替えだけを行い、変更処理を送信していません。

| 項目 | 結果 |
|---|---|
| 初期実装での連続変更 | 22回成功、52件の照合に失敗なし |
| 最終版1.0.3での連続変更 | 20回成功 |
| 最終版での操作内訳 | 通常スキルの交換・復元16回、リザーブの取り外し・再セット2回、マスタースキルの変更・復元2回 |
| 各保存の確認 | サーバーからデッキを再取得し、対象枠・交換元・重複の有無を照合 |
| テスト終了時 | cast=2は開始時の構成と一致、cast=36も開始時と一致 |
| キャスト切り替え | cast=2→36→2で各デッキに追従 |
| 枠別候補 | アシスト、ソウル、マスタースキルの分離を確認 |
| slot=9 | 使用可能レベル6以上のアシストのみ |
| リザーブ | 通常スキル・アシスト・ソウル・マスタースキルの候補を確認 |
| おすすめ順 | おすすめが先頭、枠に不適合なおすすめは表示しない |
| 一覧 | 初期48枚。追加描画で既存カード要素を維持 |
| 状態表示 | 保存状況などの更新だけでは一覧要素を再作成しない |
| 再実行 | 同じ拡張インスタンスを再表示。UI要素は1個のまま |
| カード選択画面から起動 | cast=2・type=reserve・slot=7を引き継ぎ、992件を取得 |

最終版の完了ログは `FINAL_DONE`、`saves:20`。追加確認12項目すべて `ok:true` でした。再実行のログは `RERUN_RESULT true 1 1.0.3`、選択画面からの起動も `loading:false` を確認しました。検証用のコンソールと選択画面のタブは終了済みです。

初期実装の22回にはアシスト4・9、ソウル7、マスタースキル8、複数枠の交互変更、リザーブへのマスタースキル設定を含みます。これらと最終版の20回を合計すると、実サイトで42回の保存を確認しています。

## 自動テスト

`wonder-deck.test.cjs` の23テストがすべて成功しました。通信失敗や応答の順番はテスト用APIで再現し、実サイトの通信を意図的に壊す操作はしていません。

- 通常スキルとマスタースキルの分離、slot=7・8・9の制限。
- 使用可能レベルと強化値の分離、リザーブの独立した枠番号。
- 固定枠、未所持、別キャスト、公式候補にないカードの送信前拒否。
- 20回の連続保存、装備済みカードの交換、取り外し。
- 連打による二重送信の防止、保存中のキャスト・枠切り替えの防止。
- キャスト・枠の応答順逆転、終了後の遅延応答の無視。
- 保存直前の最新デッキ照合。他画面での配置変更時は送信しない。
- 交換元に戻るカードの枠制限、保存後の重複検出。
- タイムアウト後に適用済みのケースと、結果未確定で次の保存を止めるケース。
- 候補や変更許可の失効、API拒否、再取得による復旧。
- 効果文の展開とHTMLエスケープ、検索条件のAND・OR、おすすめの枠別選別・優先順。

## 表示と負荷

PCの実サイト画面で、元のWonder.NETの背景・見出し素材、3カラム、カード名・効果文の読みやすさを確認しました。

スマホ幅は、最終ソースを組み込んだテスト用ページを390×844で表示し、デッキ・一覧の切り替え、3列のカード表示、下部の詳細パネルを確認しました。詳細パネル幅・スクロール領域幅はいずれも390pxで、横にはみ出していません。このページのデータと通信はテスト用です。

負荷対策は以下を実装しています。

- カード索引は起動中のメモリで再利用し、全キャストの候補を先読みしない。
- 検索は150msの入力待ちを設け、検索・並び替えではAPI通信しない。
- 48枚単位の追加描画、画像の遅延読込、状態表示時の一覧再作成を抑制。
- 定期ポーリングなし。終了時に監視・タイマー・未完了通信を解除。
- 通常の保存は照合を含め6リクエストを順次実行。公式画面より通信が増える点はREADMEに記載。

## 未確認事項・範囲

- **iPhone Safari実機でのブックマーク登録・起動・保存は未確認です。** PC上のスマホ幅テストは実機検証の代わりにはなりません。
- Chromeの登録用 `javascript:` URLの実行と再実行を確認しています。ユーザーのブックマークバーへの永続登録は行っていません。
- ログイン切れは検出処理とテスト用の失敗ケースで確認し、実アカウントのログインを意図的に解除していません。
- 全キャスト・全カードの組み合わせを実サイトで網羅したものではありません。実保存はcast=2だけです。
- 最新配置の取得と変更送信の間に他の画面から更新される競合を完全に防ぐには、公式API側の条件付き更新が必要です。本実装は保存前の全配置比較と保存後の照合で対処します。
- 長時間のCPU・メモリ計測、iPhoneでの消費電力・通信量の実測は行っていません。
