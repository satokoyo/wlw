# Wonder Deck 1.1.0 設計メモ

## CDNフレームワークの検討

[Preactの公式導入手順](https://preactjs.com/guide/v10/getting-started/)と[Alpine.jsの公式導入手順](https://alpinejs.dev/essentials/installation)で、CDNから利用する方法を確認しました。

今回は採用していません。現在の実装は、公式APIの正規化、装備条件、保存前後の照合、検索、専用CSSが大部分です。フレームワークを読み込んでもこれらは残り、UIのテンプレートとイベント処理を書き換える必要があります。既に一括イベント処理と差分を抑えた描画になっているため、大きなサイズ削減につながるとは判断しませんでした。CDN版を実装してサイズを実測比較した結果ではなく、現行コードの構造に基づく判断です。

外部JSなしの構成を維持し、登録URLの符号化を改善しました。同じ1.1.0の実行コードについて、すべての予約記号を符号化する方式では73,089文字、URIで安全な記号を残す方式では65,799文字となり、約10%短縮しています。`?`と`#`は明示的に符号化し、復号後のコード一致とChromeでの起動を確認しています。この比較は同一版の符号化方式の差です。機能追加を含む1.1.0全体は、旧版1.0.3の登録URL（62,802文字）より長くなっています。

v1.2.0では本体をGitHub Pagesで配信し、起動コードを1,787文字に短縮しました。バージョン固定URLとSRIで本体を検証します。参考JSONは認証情報なしで1度取得し、保存用の同一オリジンAPIとは分離します。単体版も生成します。

## 一覧の構成

- おすすめ欄を先頭に置き、公式のおすすめ順を保つ。レベルのグルーピングを行わない。
- おすすめカードも通常一覧に残す。検索結果の件数は重複を含めない。
- 検索、カテゴリタブ、詳細フィルタは両欄に適用する。
- 通常一覧は通常スキルの独立区画、レベル別のアシスト／ソウル、最後に使用レベルなしのマスタースキルとする。
- 通常一覧の同種別ではレベル昇順、レアリティ降順、同条件では公式順。マスターはレアリティ降順。
- レベル不明のアシストなどは推測せず「使用レベル未取得」に置き、その後にマスターを表示する。

## 選択不可のカード

未所持の判定には公式の所持フラグを使います。レベルがないことだけから未所持とは判断しません。

必要なメタデータの欠落は「情報未取得」として扱い、未所持と同様に薄く表示して選択不可にします。UIだけでなく保存前にも拒否します。マスタースキルには使用レベルを要求しません。

このアカウントのcast=40における「おそろいのリボン」は、おすすめデータの `ha:false` を確認しました。所持カード索引と対象枠の公式候補には含まれていませんでした。特定アカウントやカードIDを判定処理に埋め込んではいません。

## 表示と負荷

左カラムは固定のワンダースキルと重複する枠ラベル・強化値を省き、17枠をタイルで表示します。画面の高さが足りない場合にはスクロールできます。

一覧のカード名とカテゴリ・レベル等は半透明の明るい背景を付け、イラスト上に表示します。「アシスト」の代わりに「武器」などのカテゴリを表示します。

右カラムの画像はサムネイルのURLを使い、32×45pxで表示します。説明部分に高さを割り当て、保存ボタンは説明に重ならない領域に置きます。

おすすめを2か所に表示しても候補APIの追加取得は発生しません。通常一覧は48枚ずつ、おすすめ欄は公式件数分だけ描画します。検索・カテゴリ切り替え・追加描画は取得済みデータだけで処理し、定期通信は行いません。
